# PromptDock Web

PromptDock 是本机运行的 `AGENTS.md` 规则管理器。浏览器呈现工作台，Node 服务负责扫描和写入工作空间，并在本地 Git 中记录候选历史。规则正文不会上传。

## 运行

要求 Node.js 20+、pnpm 和可从终端调用的 Git（候选历史使用本地 Git）。在项目目录执行：

```powershell
pnpm install
pnpm dev
```

开发页面位于 `http://127.0.0.1:5173`，本地 API 位于 `http://127.0.0.1:4317`。日常单进程模式：

```powershell
pnpm build
pnpm start
```

然后打开 `http://127.0.0.1:4317`。服务只监听本机回环地址；停止终端中的进程即可结束服务，不安装后台守护进程。

Windows 可双击项目目录中的 `启动 PromptDock.cmd`：脚本先构建，再启动服务并打开默认浏览器。关闭启动窗口会结束服务。

## 真实浏览器验收

首次运行安装 Playwright Chromium：

```powershell
pnpm exec playwright install chromium
```

随后执行 `pnpm test:e2e`。验收会构建正式前端、启动本地 Node 服务并操作真实浏览器；用户规则、工作空间和应用数据都放在系统临时目录，结束后自动清理。

## 使用规则

1. 用户级 Codex 规则作为普通路径自动添加并排在工作空间列表顶部；默认位置是 `CODEX_HOME/AGENTS.md`，未设置 `CODEX_HOME` 时是 `~/.codex/AGENTS.md`。
2. 添加工作空间时粘贴本机绝对目录路径。服务递归扫描其中的 `AGENTS.md`；之后可手动重扫，每次打开或重新加载工作台也会重扫所有已登记路径。扫描不跟随符号链接。有未保存草稿时，手动重扫会先询问，因为扫描可能发现冲突并切换到解决页；取消不会发起扫描，确认后若发生冲突，可将草稿放入解决稿继续合并。已编辑的冲突解决稿也会在重扫前提示；确认重扫后解决稿保留，冲突两侧刷新，如需使用新正式内容可明确载入解决稿。切换工作空间或规则路径、添加并切换工作空间、移除当前工作空间时，未保存的候选（名称或正文）或冲突解决稿（候选名称或正文）也会先询问；取消保留当前编辑位置和草稿，确认后离开即丢弃。
   工作空间行末的移除按钮只取消路径登记，不删除正式文件、候选或本地历史；之后重新添加相同路径即可继续管理。自动登记的用户级规则路径不能移除。
3. 已存在的规则会被导入为候选并立即锁定。没有规则的目录不会自动创建候选；使用“初始化 AGENTS.md”明确创建正式文件和首个锁定候选。
4. 新建候选可复制编辑器当前内容（包括未保存修改），也可从此路径的任一已保存候选创建分支；若当前编辑器有未保存修改，从已保存候选分支会保留原编辑器和草稿，新候选加入列表但不抢占编辑位置。也可以从本机 `.md`／`.markdown` 文件导入为未锁定候选。导入不会修改来源文件或正式文件。候选可单独编辑和保存；每次保存都记入本地 Git。锁定候选保存时同时更新工作空间中的正式文件。
5. 正式文件与锁定候选不一致时显示冲突，并阻止切换。冲突页默认标出从正式文件到锁定候选的逐行新增和删除，也可并排查看原文。可将正式文件、锁定候选或未保存草稿放入解决稿再手动合并；保存解决稿会创建新候选，同时同步正式文件并锁定它。
6. 候选历史可以查看每次保存的 Git 快照，并逐行比较所选快照与当前编辑器草稿（包含未保存修改）；历史全文也可单独查看。查看只读，不会改写候选或正式文件。选择旧快照后会创建一个新的候选，不会回滚历史或直接覆盖正式文件。
7. 实验候选可与正式版或其他候选比较；左侧使用当前编辑器内容（包括未保存草稿），右侧可选择已保存基准。支持逐行标记差异或并排原文；对比窗口只读，不会修改任何文件。
8. 编辑器可在编辑和 Markdown 预览间切换；预览随当前草稿即时更新，支持 GFM 表格和任务列表，不会保存内容。原始 HTML 不渲染，图片链接显示占位文字而不发起网络请求。候选编辑区和冲突解决稿都会实时显示当前草稿的行数、Unicode 码点数和 UTF-8 字节数；空内容计一行，末尾换行后的空行也计入，帮助发现规则文件体量变化。
9. 候选区可按名称或正文搜索；搜索只隐藏暂时不匹配的行，不会切换或删除候选。
10. “复制内容”会将当前编辑器正文（包括未保存修改）复制到系统剪贴板，方便直接粘贴到其他工具；复制成功后按钮短暂显示“已复制”。冲突页的“复制解决稿”会复制未保存的合并文本。正式文件卡片中的“复制路径”会复制完整 `AGENTS.md` 绝对路径。“导出 Markdown”会下载当前编辑器内容。这些操作都不会改变候选、历史或正式文件。
11. 在候选名称或正文编辑框按 `Ctrl+S`（macOS 为 `⌘S`）保存当前候选；冲突解决稿仍通过“保存解决结果”明确提交。候选有未保存修改时可“还原已保存版本”，经确认后恢复此候选最近保存的名称和正文，不改磁盘或历史。任一弹窗都可按 `Esc` 关闭，效果等同于关闭按钮，不会保存或提交内容。刷新或关闭页面时，浏览器会对未保存候选或冲突解决稿显示离开确认；取消离开会保留当前草稿。

## 本地数据与诊断

- 候选、工作空间登记、锁定状态和 Git 历史在本机应用数据目录的 `PromptDock/Web/library` 下。
- 诊断日志在同级 `logs/promptdock.jsonl`，只记录操作事件、路径、耗时和错误摘要，不记录规则正文。
- 默认数据目录是 Windows `%LOCALAPPDATA%/PromptDock/Web`、macOS `~/Library/Application Support/PromptDock/Web`、Linux `$XDG_DATA_HOME/promptdock/web`（未设置时 `~/.local/share/promptdock/web`）。
- 可设置 `PROMPTDOCK_DATA_DIR` 将应用数据放到指定目录，便于隔离测试或备份。

纯浏览器无法获得系统目录选择器返回的任意本机路径，因此添加工作空间使用路径输入框；实际文件操作仍由本机 Node API 完成。
