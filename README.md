# PromptDock Web

PromptDock 是本机运行的 `AGENTS.md` 文件管理器，核心模型是磁盘文件与缓存：每个目标路径下只有一个实际生效的磁盘文件；应用可保存多个持久化缓存版本，切换缓存会将所选版本写入磁盘文件。当前缓存与磁盘文件保持一致；外部修改造成两者不一致时，需要先合并再恢复一致。浏览器提供文件管理界面，Node 服务负责扫描和写入工作空间，并在本地 Git 中记录缓存版本历史。文件内容不会上传。

## 运行

要求 Node.js 20+、pnpm 和可从终端调用的 Git（缓存版本历史使用本地 Git）。在项目目录执行：

```powershell
pnpm install
pnpm dev
```

开发页面位于 `http://127.0.0.1:5173`，本地 API 位于 `http://127.0.0.1:4317`。日常单进程模式：

```powershell
pnpm build
pnpm start
```

然后打开 `http://127.0.0.1:4317`。服务只监听本机回环地址；停止终端中的进程即可结束服务，不安装后台守护进程。

Windows 可双击项目目录中的 `启动 PromptDock.cmd`：脚本先构建，再启动服务并打开默认浏览器。关闭启动窗口会结束服务。

## 真实浏览器验收

首次运行安装 Playwright Chromium：

```powershell
pnpm exec playwright install chromium
```

随后执行 `pnpm test:e2e`。验收会构建生产前端、启动本地 Node 服务并操作真实浏览器；用户文件、工作空间和应用数据都放在系统临时目录，结束后自动清理。

## 使用说明

1. Codex 用户文件作为普通路径自动添加并排在工作空间列表顶部；默认位置是 `CODEX_HOME/AGENTS.md`，未设置 `CODEX_HOME` 时是 `~/.codex/AGENTS.md`。
2. 添加工作空间时可用系统文件夹选择器，也可输入本机绝对目录路径。服务递归扫描其中的 `AGENTS.md`；之后可手动重扫，每次打开或重新加载文件管理也会重扫所有已登记路径。打开时先显示本地保存的工作空间与文件，再在后台重扫并更新列表；扫描期间顶部状态提示显示进度状态。扫描不跟随符号链接。同名工作空间会附带父路径缩写，避免把不同目录误认成同一路径。有未保存草稿时，手动重扫会先询问，因为扫描可能发现冲突并切换到解决页；取消不会发起扫描，确认后若发生冲突，可将草稿放入解决稿继续合并。已编辑的冲突解决稿也会在重扫前提示；确认重扫后解决稿保留，冲突两侧刷新，如需使用新磁盘文件内容可明确载入解决稿。切换工作空间或文件路径、添加并切换工作空间、移除当前工作空间时，未保存的缓存（名称或正文）或冲突解决稿（缓存名称或正文）也会先询问；取消保留当前编辑位置和草稿，确认后离开即丢弃。
   工作空间行末的移除按钮只取消路径登记，不删除磁盘文件、缓存或本地历史；之后重新添加相同路径即可继续管理。自动登记的用户文件路径不能移除。
3. 发现磁盘文件时，会将其内容导入为首个缓存版本并设为当前缓存。没有磁盘文件的目录不会自动创建缓存版本；使用“初始化 AGENTS.md”明确创建磁盘文件和首个缓存版本，并设为当前缓存。
4. 新建缓存版本可复制编辑器当前内容（包括未保存修改），也可从此路径的任一已保存缓存 Fork 一份；弹窗可展开只读预览来源正文。若当前编辑器有未保存修改，从已保存缓存 Fork 会保留原编辑器和草稿，新缓存版本加入列表但不抢占编辑位置。也可以从本机 `.md`／`.markdown` 文件 Fork 一个缓存版本（未设为当前缓存）。Fork 不会修改来源文件或磁盘文件。缓存可单独编辑和保存；每次保存都记入本地 Git。保存时服务端会核对页面打开时的缓存名称和正文；如果另一个窗口已经保存了新版本，过期保存会被拒绝，当前草稿保留，可用“新建缓存”另存。保存当前缓存时同时更新工作空间中的磁盘文件；当前缓存有未保存修改时，编辑器会显示本次同步对磁盘文件新增和删除的行数。
   切换当前缓存前会先检查最新磁盘文件状态，再显示所选缓存与磁盘文件的逐行差异及增删行数；发现外部修改会先进入冲突处理。只有确认后才写入磁盘文件，服务端也会在确认时再次检查。取消预览不改动文件或当前缓存标记。
5. 磁盘文件与当前缓存不一致时显示冲突，并阻止切换。冲突页默认标出从当前缓存到磁盘文件的逐行新增和删除，也可并排查看原文。可将磁盘文件、当前缓存或未保存草稿放入解决稿再手动合并；保存解决稿会创建新缓存，同时同步磁盘文件并将新版本设为当前缓存。
6. 缓存历史记录每次保存，包括只改缓存名称的保存；快照可逐行比较正文，也能查看当时的缓存名称。历史视图只读，不会改写缓存或磁盘文件。可直接导出选中的历史快照为 Markdown；也可按旧快照的名称和正文创建一个新缓存，不会回滚历史或直接覆盖磁盘文件。
7. 其他缓存版本可与磁盘文件或其他缓存比较；对比基准下拉框按“磁盘”“缓存”“已归档”分组。左侧使用当前编辑器内容（包括未保存草稿），右侧显示所选基准。当前缓存正文有未保存修改时，可直接预览草稿与磁盘文件的差异。支持逐行标记差异或并排原文；该预览只读，编辑当前缓存的正文只会在保存时同步磁盘文件。
8. 编辑器可在编辑和 Markdown 预览间切换；预览随当前草稿即时更新，支持 GFM 表格和任务列表，不会保存内容。原始 HTML 不渲染，图片链接显示占位文字而不发起网络请求。缓存编辑区和冲突解决稿都会实时显示当前草稿的行数、Unicode 码点数和 UTF-8 字节数；空内容计一行，末尾换行后的空行也计入，帮助发现文件体量变化。
9. 缓存版本列表可按名称或正文搜索；搜索只隐藏暂时不匹配的行，不会切换或删除版本。列表上方可重命名或删除选中的缓存版本；重命名会记入本机历史，不更改正文，当前缓存不可删除。删除会将版本从列表和搜索结果中移除，旧的 Git 历史记录仍保留在本机。同一路径存在同名版本时，列表会附加各自 ID 前 7 位，方便区分并选择准确版本。
10. “复制内容”会将当前编辑器正文（包括未保存修改）复制到系统剪贴板，方便直接粘贴到其他工具；复制成功后按钮短暂显示“已复制”。冲突页的“复制解决稿”会复制未保存的合并文本。磁盘文件信息卡片中的“复制路径”会复制完整 `AGENTS.md` 绝对路径。“导出 Markdown”会下载当前编辑器内容。这些操作都不会改变缓存、历史或磁盘文件。
11. 在缓存名称或正文编辑框按 `Ctrl+S`（macOS 为 `⌘S`）保存当前缓存；冲突解决稿仍通过“保存解决结果”明确提交。缓存有未保存修改时可“还原已保存版本”，经确认后恢复此缓存最近保存的名称和正文，不改磁盘或历史。任一弹窗都可按 `Esc` 关闭，效果等同于关闭按钮，不会保存或提交内容。刷新或关闭页面时，浏览器会对未保存缓存或冲突解决稿显示离开确认；取消离开会保留当前草稿。
12. 非当前缓存可归档以收起试验版本；归档只改变缓存的本地管理状态并记入历史，不删除正文、版本记录或磁盘文件。可在“已归档”列表查看只读内容并恢复；当前缓存不能归档，冲突时不能归档或恢复。
13. 顶部“搜索全部文件”或 `Ctrl+Shift+F`（macOS 为 `⌘⇧F`）会搜索当前登记工作空间下所有已扫描路径的磁盘文件和缓存正文，包括已归档缓存；磁盘文件与当前缓存内容相同时只显示一次，发生冲突时两侧分别显示。移除工作空间后，保留的缓存和历史不再出现在搜索中；重新添加路径后可再次搜索。点击结果可打开对应路径和缓存；若当前有未保存草稿，需要确认后才会离开。
14. 编辑缓存时可查找当前正文中的原文并逐处或全部替换；匹配区分大小写。替换只改变当前草稿，保存前不会写入缓存或磁盘文件；保存当前缓存时仍会同步磁盘文件。

## 本地数据与诊断

- 缓存、工作空间登记、当前缓存状态和 Git 历史在本机应用数据目录的 `PromptDock/Web/library` 下。
- 诊断日志在同级 `logs/promptdock.jsonl`，只记录操作事件、路径、耗时和错误摘要，不记录文件正文。
- 默认数据目录是 Windows `%LOCALAPPDATA%/PromptDock/Web`、macOS `~/Library/Application Support/PromptDock/Web`、Linux `$XDG_DATA_HOME/promptdock/web`（未设置时 `~/.local/share/promptdock/web`）。
- 可设置 `PROMPTDOCK_DATA_DIR` 将应用数据放到指定目录，便于隔离测试或备份。

纯浏览器无法获得系统目录选择器返回的任意本机路径，因此添加工作空间使用路径输入框；实际文件操作仍由本机 Node API 完成。
